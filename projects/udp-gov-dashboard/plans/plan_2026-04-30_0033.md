## Context

The Tag Taxonomy section currently uses a `StepSidebar` + `DetailPanel` pattern — click a tag name, read a static card. The schema and policy sections are meaningfully interactive: schema lets you explore 6 access models, policy has a live RAP playground. Tags should match that level.

**Key insight:** The story of tags is *combination and cascade*. You don't use one tag at a time — you apply all four to a table, and the combination resolves to a specific schema, bound policy, and enforcement behavior.

## Design: Tag Resolution Playground

Replace the current sidebar/detail-panel with a two-column interactive layout (matching the policy playground pattern):

**Left column (sticky):** Tag Selector strip — one row per tag with clickable value chips. The user picks a value for each of the 4 tags. This is like the user-selector dropdown in the policy section but for tag values.

Example layout:
```
DATA_DOMAIN       [ SALES ] [ HR ] [ FINANCE ]
DATA_SENSITIVITY  [ PUBLIC ] [ INTERNAL ] [ RESTRICTED ]
GOVERNANCE_GRAIN  [ OPP_ID ] [ REGION ] [ DEPARTMENT ] [ GLOBAL ]
PII_POLICY        [ None ] [ EMAIL ] [ FULL_NAME ] [ SSN_LAST4 ]
```

Each chip is a button. Active chip gets the tag's color highlight. Default selection: SALES / RESTRICTED / REGION / None.

**Right column:** Resolution chain — a live-updating cascade showing what the selected combination resolves to:

1. **Resolved Schema** — e.g. `SALES__BY_REGION` (derived from domain + grain). Highlights the matching schema name + its policy name + grain columns. If no exact match, shows a "no matching schema" state.
2. **Bound RAP** — shows which policy binds (e.g. `unified_sales_policy`) and which CASE branch the grain activates
3. **Masking Status** — based on DATA_SENSITIVITY and PII_POLICY selection: "Column masking active on EMAIL, FULL_NAME" or "No masking — PUBLIC data" or "No PII columns tagged"
4. **Enforcement Summary** — 2-3 short lines: what the tag combination means in practice

The resolution is pure derived state from the existing `schemas[]` array — `domain` matches `DATA_DOMAIN`, grain maps to schema naming convention. No new data needed beyond a small resolution map and a few masking descriptions.

**PII Interaction section stays** — it's already interactive (conflict toggle) and complements the playground.

2. **Add state** — replace `activeTag` with 4 independent state variables: `selectedDomain`, `selectedSensitivity`, `selectedGrain`, `selectedPii`. Each defaults to a sensible value.

3. **Build Tag Selector strip** (left column) — 4 rows, each with the tag name and clickable value chips. Active chip uses the tag's color from `colorStyles`. Compact layout, similar density to the RAP user selector.

4. **Build Resolution Panel** (right column) — live-updating card showing resolved schema, bound RAP, masking status, and enforcement summary. Masking status is conditional (red if PII columns present + RESTRICTED, green if PUBLIC/no PII).

6. **Clean up dead code** — remove `activeTag` state, `tagStyle` derived var, `StepSidebar`/`DetailPanel` imports if no longer used elsewhere (check — schema section uses `DetailPanel`; `StepSidebar` may become unused).

## Context

Audited the 5 components on the eng overview plus all `§N` references across the codebase. Two changes requested:

1. **Remove all `§N` section references** — badges, narrative connectors, cross-references, roadmap chips, internal labels
2. **Re-evaluate overview composition** — are these components pulling their weight for an engineering audience?

### Component-by-component assessment

| Component | What it renders | Verdict | Reasoning |
|---|---|---|---|
| **HeroBlock** | Badge + title + 1-paragraph thesis | **Keep, simplify** | Every page needs a header. Remove the `§1 · Architecture Overview` badge text — just say "Engineering Overview". |
| **KeyConceptsGrid** | 7-card glossary (PDP, PEP, RAP, CTAS, ENTITLEMENTS, RLS, RBAC) | **Cut** | Engineers don't need a glossary wall. These terms are defined in context on the pages that use them (PDP/PEP in Enforcement, RAP in Policy, CTAS in Schema). The glossary front-loads jargon before the reader has context to understand it. |
| **GovernanceChallenge** | Interactive 3-PEP sidebar (Snowflake/S3/Bedrock) | **Cut** | This is a redundant preview of the Extensibility page (§7). The interactive sidebar duplicates the HubSpokeDiagram. Exec mode needs this because execs won't click to another tab — engineers will. |
| **CoreVulnerabilities** | Interactive 4-vulnerability sidebar (CTAS trap, Decentralized SQL, Grain Change, Mapping Bottleneck) | **Keep, rework** | This is the strongest component — it establishes *why* the architecture exists. But the interactive sidebar with prev/next is overkill for 4 short items. A flat 2×2 card grid would be faster to scan and more appropriate for an overview. |
| **DocumentRoadmap** | Clickable §1–§8 chips | **Replace** | The chips reference section numbers we're removing. Replace with a simpler "What's covered" list that names each topic and links to the tab, without numbering. |
| **Bottom Line** | Emerald closer | **Keep, rewrite** | Remove section number references from the copy. |

### Proposed new eng overview flow

```
HeroBlock (badge: "Engineering Overview")
→ CoreVulnerabilities (reworked as flat 2×2 grid, no sidebar)
→ "What's Covered" nav (replaces DocumentRoadmap, no §N chips)
→ Bottom Line closer
```

This cuts the page from 5 content blocks + closer to 2 content blocks + nav + closer. Each block earns its spot: the vulnerabilities establish the "why", the nav provides wayfinding, and the closer frames the thesis.

## Context

The current narrative frames governance as a strict `Tags → Schemas → Policy` dependency chain where tags *drive* schema placement. In reality:

- **Schema placement** is the enforcement mechanism — a table in `SALES__BY_REGION` gets the RAP immediately, no tags required
- **Tags** are classification metadata applied in parallel (by dbt or manually) — they drive PII masking policies and enable catalog/audit queries, but do not determine which schema a table lands in
- **The RAP** reads schema name + `ENTITLEMENTS` table at query time — it never reads tag values

Six text sections contain inaccurate causal claims about tags.

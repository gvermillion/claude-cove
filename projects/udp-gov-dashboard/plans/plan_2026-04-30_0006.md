## Context

The three pages (Schema Design, Tag Taxonomy, Policy Logic) are facets of a single system — **how governance is implemented**. They cross-reference each other heavily and share the same conceptual objects (tags, schemas, RAPs, ENTITLEMENTS). Hardening/Enforcement is a separate concern (operational security of the ENTITLEMENTS table and sandboxes) but currently lives as a peer tab.

### Current sidebar
```
Overview → Developer Experience → Schema Design → Tag Taxonomy → Policy Logic → Hardening → Extensibility → Roadmap & Ops
```

### Problem
1. **"Hardening Controls"** subsection in Developer Experience sidebar is stale (content was removed last edit)
2. Schema / Taxonomy / Policy are presented as 3 separate tabs but the reader has to mentally stitch them together — the story is fragmented
3. Enforcement/Hardening mixes two concerns: ENTITLEMENTS lifecycle (which is really part of the governance implementation story) and sandbox hardening (which belongs closer to Developer Experience)

## Proposed restructure

### Merge Schema + Taxonomy + Policy into one page: **"Governance Implementation"**

One page, three sections, top-to-bottom narrative:

```
1. Tags        — the metadata vocabulary (what drives everything)
2. Schemas     — how data is organized by security grain (where tags land)
3. Policy      — the RAP that reads tags and evaluates ENTITLEMENTS (how access is enforced at query time)
```

This matches the natural dependency chain: tags → schemas → policy. The reader sees the full implementation in one scroll rather than clicking between three tabs.

Each former page becomes a `<section>` within the unified view. The interactive elements (tag selector, schema selector, RAP playground) all stay — they just live on one page with clear `<h3>` section headers.

### Restructure Hardening

- **ENTITLEMENTS lifecycle** + governance architecture + defense-in-depth stay in Hardening (renamed to **"Enforcement & Hardening"**) — this is operational security
- **Sandbox hardening** stays there too (it's about the enforcement layers, not the dev experience)
- Remove the cross-reference link from SchemaView's PDP callout (it'll be on the same conceptual page now, or one tab away)

### New sidebar
```
Overview
Developer Experience        (subsections: Thesis, CoCo + Stages, Two Paths)
Governance Implementation   (subsections: Tag Taxonomy, Schema Design, Policy Logic)
Enforcement & Hardening     (subsections: Architecture, Defense in Depth, ENTITLEMENTS Lifecycle, Sandbox Hardening)
Extensibility
Roadmap & Ops
```

6 tabs instead of 8. The three implementation facets are unified. The reader gets the "how it's built" story in one place.
